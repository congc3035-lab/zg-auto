# L3 Domain 实施计划

> **给执行者**：本计划按 [开发契约](../../CONTRIBUTING.md) 第 3 步逐任务执行。
> 步骤用 `- [ ]` 复选框跟踪。每个任务独立走完红绿循环并提交，不得批量实现后补测试。

**目标**：建立 L3 Domain 层——时间窗口判定、页面解析、编队守卫。**仍不包含任何 Task**。

**架构**：L3 把游戏语义封装成纯函数与受控操作。解析部分是 `(html) => value` 纯函数，
可脱离浏览器测试；编队操作通过注入的 Gateway 执行，测试时替换为假实现。

**技术栈**：原生 JavaScript（ES2020），Node 20 内置 test runner，零第三方依赖。

**规格**：[需求规格 V0.4](../01-需求规格.md)、[架构设计 V1.0](../02-架构设计.md)

**前置**：[L1+L2 计划](2026-08-31-l1-core-l2-gateway.md) 已完成，28 个测试全绿。

## 全局约束

取自规格，**每个任务都隐含包含**：

- 相邻请求间隔**不得低于 800 毫秒**（由 L1 的 `createHttp` 保证）
- 所有站点访问**必须经 Gateway**，L3 禁止出现 `fetch` / `http.get` / `location.href =`
- 编队是全局状态，**任何切换都必须有 finally 兜底**
- 好友属地**只开发等级 ≥ 40 的好友**，不降格
- 单文件**不超过 1200 行**（当前 203 行）
- Gateway 公开函数**冻结为三个**，本计划不得新增

## 本计划需要批准的四项

### 一：`resources` 拆分为按页面解析

架构原文写的是 `resources.read() -> { orders, activity, copper, food }`。
但**活跃度不在 `/Mine` 页面上**，它在 `/Act/Daily/Index`。
一个函数解析两个页面会让它既不纯也难测。

**决定**：改为 `parse.mine(html) -> { orders, copper, food, merit, prestige }`，
只解析 `/Mine`。活跃度留给日常任务自己解析，届时另加 `parse.dailyActivity`。

### 二：编队切换的实际请求数是 6 个，不是 3 个

架构文档说「切换一次需 3 个请求」。实测编队操作链接**不带 `_r` token**：

```
/Build/Operate/Down?a=1&sid=...
/Build/Operate/UpOk?g=<GUID>&a=0&sid=...
```

理论上可以连发 3 个。但 `gw.act` 的契约是「每次动作前重取列表页」，
因此走 Gateway 实际是 6 个请求（3 读 + 3 写）。

**决定**：仍然走 `gw.act`，不为编队开特例。理由是 R5 已把 Gateway 冻结为三个函数，
为省 3 个请求去开后门，等于把「唯一写入口」这条最重要的约束撕开一个口子。
代价是每次切换多约 2.4 秒（3 次节流），完全可接受。

### 三：`four` 状态的 fixture 由 `solo` 版本改造

勘察时发现**账号当前编队处于 `solo` 状态**（仅王翦在前军，其余三位空闲），
因此只能抓到真实的 `solo` 页面。`four` 状态的 fixture 将基于真实结构手工改造
（把三个「空闲」替换为对应武将的链接与下阵按钮），并在文件头注明来源。

这是本计划里唯一一处非纯真实数据，如实标注。

### 四：阵位解析基于「是否空闲」而非「是否有链接」

页面里空位渲染为 `<span>空闲</span>`，有人则渲染为 `<span><a ...>武将名</a></span>`。
判据取「该阵位后的 span 内是否含『空闲』」，比判断有无链接更稳——
护卫位与援军位也会渲染 span，但内容是「(校场45级后可消耗1个英雄令开启)」，
若按有无链接判断会误判。本计划只查先锋 / 前军 / 中军 / 后卫四位。

```js
  //  ── L3 Domain ──────────  parse / formation / windows

  // ranges 形如 [[12,13],[18,19]]，含起点不含终点。
  // date 由调用方注入，便于测试；生产代码传 new Date()。
  function isWindowOpen(ranges, date) {
    if (!Array.isArray(ranges) || ranges.length === 0) return false;
    var h = date.getHours();
    for (var i = 0; i < ranges.length; i++) {
      if (h >= ranges[i][0] && h < ranges[i][1]) return true;
    }
    return false;
  }
```

- [ ] **Step 3：写最小实现**

```js
  // 阵位判据取「该阵位后的 span 内是否含『空闲』」。
  // 不按有无链接判断：护卫位与援军位也渲染 span，内容是开启条件说明，
  // 按链接判断会把它们误算成有人。
  function slotOccupied(text, label) {
    var re = new RegExp(label + '\\s*[:：][\\s\\S]{0,40}?<span>([\\s\\S]{0,120}?)<\\/span>');
    var m = re.exec(text);
    if (!m) return false;
    return m[1].indexOf('空闲') === -1;
  }

  // four = 四位皆有人；solo = 仅前军有人；其余一律 other。
  // other 出现时上层必须先修复为 four 再继续，详见架构设计的三重保护。
  function parseFormation(html) {
    var text = decodeEntities(html);
    var van = slotOccupied(text, '先锋');
    var front = slotOccupied(text, '前军');
    var center = slotOccupied(text, '中军');
    var rear = slotOccupied(text, '后卫');
    if (van && front && center && rear) return 'four';
    if (!van && front && !center && !rear) return 'solo';
    return 'other';
  }
```

```js
  // 好友条目形如：
  //   <a href="/Build/Operate/FColony?f=555555&amp;sid=...">昵称</a>(50&#x7EA7;)
  // 先整体解码，再一次性捕获 id、昵称、等级三段。
  function parseFriendList(html) {
    if (typeof html !== 'string' || html === '') return [];
    var text = decodeEntities(html);
    var rx = /href=["'](\/Build\/Operate\/FColony\?f=(\d+)[^"']*)["'][^>]*>([\s\S]*?)<\/a>\s*\((\d+)级\)/g;
    var out = [];
    var m;
    while ((m = rx.exec(text)) !== null) {
      out.push({
        href: m[1],
        id: m[2],
        name: m[3].replace(/<[^>]*>/g, '').trim(),
        level: parseInt(m[4], 10)
      });
    }
    return out;
  }
```

```js
  // 阵位号：0 先锋 / 1 前军 / 2 中军 / 3 后卫。
  // 王翦固定占前军(1)，两套阵型都不动它，因此切换只涉及 0 / 2 / 3 三位。
  //
  // 每个动作都走 gw.act，因此实际请求数是 6 个（3 读 + 3 写）而非 3 个。
  // 编队链接本身不带一次性 token，理论上可以直接连发，
  // 但为守住「Gateway 是唯一写入口」这条约束，不为编队开特例。
  async function ensureFormation(deps, kind) {
    var gw = deps.gw;
    var g = deps.generals;
    var cur = parseFormation(await gw.read(CFG.formationPath));
    if (cur === kind) return cur;

    if (kind === 'solo') {
      var slots = [0, 2, 3];
      for (var i = 0; i < slots.length; i++) {
        await gw.act(CFG.formationPath, new RegExp('Down\\?a=' + slots[i]));
      }
    } else if (kind === 'four') {
      var ups = [[g.sima, 0], [g.yue, 2], [g.wu, 3]];
      for (var j = 0; j < ups.length; j++) {
        await gw.act(
          CFG.formationPath,
          new RegExp('UpOk\\?g=' + ups[j][0] + '[^"\']*a=' + ups[j][1])
        );
      }
    }

    return parseFormation(await gw.read(CFG.formationPath));
  }
```
